# Brand

The brand is an otter. There are two marks, both hand-written SVGs on a 128x128 viewBox:

- **Otter face** — the _icon_. Front-facing otter head in a teal circle. Works down to 16 px, so
  it's the one for favicons, avatars, and small credits.
- **Otter-R** — the _logo_. An otter peeking over a big R. Needs at least ~32 px; use it where
  there is room (site header, OG cards, documents, banners).

Colours: brand teal `#1a9d8b` (dark backgrounds: `#21c4ae`, matching the site's dark theme),
otter browns `#8b5a34` / `#6b4226` / `#3d2414`, face `#c08a5a`, muzzle `#f1dfc4`.

## Files

```
brand/
  svg/                       # Source of truth. Edit these.
    otter-face.svg           # Icon, colour.
    otter-face-square.svg    # Icon on a full-bleed teal square (apple-touch-icon; iOS rounds it).
    otter-face-mono.svg      # Icon, one colour (currentColor).
    otter-r.svg              # Logo, colour, for light backgrounds.
    otter-r-dark.svg         # Logo with the brighter teal R, for dark backgrounds.
    otter-r-mono.svg         # Logo, one colour (currentColor).
  png/                       # Generated by `pnpm brand:export`. Don't edit.
  credit/credit.html         # Copy-paste footer credit for client sites (open it to preview).
scripts/brand/export.ts      # The PNG/ICO exporter.
```

`pnpm brand:export` renders the PNGs (avatar sizes 32/128/512/1024, logos at 1200), builds a
16/32/48 `favicon.ico`, and writes the site assets: `public/favicon.ico`,
`public/apple-touch-icon.png`, and `src/assets/og-logo.png` (the logo on OG cards, see
[seo.md](seo.md)). It borrows `sharp` from Astro's dependencies instead of adding its own.

Two copies are **not** generated and must be synced by hand when a mark changes:

- `public/favicon.svg` — `otter-face.svg` plus a `prefers-color-scheme` style for the circle.
- The inline otter-R in [Header.astro](../src/components/site/Header.astro) — the R uses
  `text-brand` so it follows the theme, and the otter's head moves up on hover.

**Verify after editing:** run `pnpm brand:export`, open the PNGs in `brand/png/`, open
`brand/credit/credit.html`, and check the header in both themes with `pnpm dev`.

### One-colour SVG gotchas

- The cut-outs (eyes, muzzle) are SVG masks. Mask contents need an explicit `fill="#000"`:
  otherwise they inherit `fill="currentColor"` from the root and only partially cut with light
  colours.
- Mask IDs are prefixed (`rr-…`) so they don't clash with IDs on a client's page.

## Where to use which

| Place                           | Mark                                                     |
| ------------------------------- | -------------------------------------------------------- |
| Favicon, apple-touch-icon       | Otter face                                               |
| Site header, OG cards           | Otter-R                                                  |
| GitHub / X / dev.to avatar      | Otter face (`otter-face-1024.png`)                       |
| LinkedIn                        | Keep the personal photo; use the otter-R in the banner   |
| Email signature                 | `otter-face-128.png` (PNG: many mail clients block SVG)  |
| Invoices, proposals, letterhead | Otter-R                                                  |
| Stickers, business cards        | Otter-R; print shops want a vector PDF made from the SVG |
| Footer credit on client sites   | Otter face, colour or one-colour (see below)             |

## Credits on client sites

Copy a snippet from [brand/credit/credit.html](../brand/credit/credit.html): the **colour badge**,
or the **one-colour** version that follows the footer's text colour (use it when the teal clashes
with the client's palette). Then:

- Replace `CLIENT` in `?utm_source=CLIENT&utm_medium=credit` with a short client slug. Umami
  groups these in its UTM report, so you can see which client site sends visitors.
- Ship the SVG inline (as the snippet does), never hotlinked from robinreinecke.de: hotlinked
  credits break when this site changes, and every client page view would hit this server.
- Keep the link text your name. Keyword-rich footer links spread across many sites count as link
  spam for Google. Add `rel="nofollow"` if you want to be fully on the safe side.
- Agree on the credit in the contract (e.g. "small footer credit, removable on request").
